# 移动 App 页面框架审查与整改

## 根因

首页和个人页原先用 390×844 固定画布/FittedBox，卡包页用真实屏幕 SafeArea。
虽然复用了 BrandLockup，但品牌位置与缩放由页面分别决定。
测试曾复现品牌矩形从 Rect(284.1, 41.2, 409.4, 59.7) 跳到 Rect(48, 12, 224.2, 38)。

## 本次全部整改范围

| 页面/问题 | 完成的整改 |
| --- | --- |
| 首页、卡包、个人页 | 统一 PrimaryPage；品牌固定，内容滚动，导航空间统一。首页卡包与卡包列表改为自然内容高度；平板维持两列。 |
| 登录、引导页 | 复用同一品牌头部；表单/步骤可滚动，移除固定画布和固定表单高度；小屏可完成全部引导。键盘出现时表单缩小可视区域，品牌不缩放、不移动。 |
| 卡包详情、OCR 结果、草稿审阅 | 使用共用返回栏、安全区、宽度约束。内容滚动，主要操作放在安全区内的独立底栏。 |
| 草稿编辑器 | 共用返回栏和完成操作；字段列表适应键盘。 |
| 学习、结果页 | 改用 AppSurface，共享 Scaffold、背景与安全区；保留各自的卡片高度、手势和结果展示算法。 |
| 拍照批次、Card Agent、卡片编辑器 | 改用 AppPage，共享返回栏、最大宽度与安全区。编辑器整体可滚动；聊天保留消息区及输入区。 |
| 卡包市场 WebView | 复用二级页面外壳及返回操作；网页视口允许全宽。 |
| MainShell 加载、失败重试 | 使用 PrimaryPage，在数据返回前后保持品牌几何连续。 |
| 旧 GradientPage 默认缩放路径 | 已删除 adaptiveLayout 双模式和固定画布/FittedBox 分支，只保留真实视口背景。 |
| 小屏与放大字体 | 修复登录按钮、引导进度、卡包统计、首页卡包及卡包列表溢出；账户长名称和邮箱可换行。 |

## 共享结构与新页面约定

- `AppLayout`：断点、水平边距、内容最大宽度、品牌顶部位置、头部间距、导航高度与底部间距的唯一来源。
- `DesignCanvas`：底层 Scaffold/RepaintBoundary。保留旧测试截图 key，已无整页缩放职责。
- `GradientPage`：只负责背景，不负责缩放页面。
- `AppSurface`：统一 Scaffold、背景、SafeArea 和键盘避让；用于学习等有独立内容布局的全屏流程。
- `AppPage`：统一品牌或返回栏、内容容器、操作底栏；页面只提供业务内容。
- `PrimaryPage`：AppPage 的主 Tab 配置，统一预留导航空间。
- `MainShell`：保留 IndexedStack 与唯一主导航，切换时保留页面状态。

普通业务页面不得自行添加 Scaffold、固定坐标品牌、整页 FittedBox 或第二个主导航。
长内容使用滚动容器，不再用固定画布高度容纳表单或列表。

保留的局部定位属于必要的内容实现：启动动画的层叠、学习卡片拖拽反馈、主导航停靠。
卡片编辑器的 FittedBox 只缩放预览卡片，品牌头部的 FittedBox 只缩放进度装饰，均不缩放页面或品牌。
个人页弹出设置面板的 SafeArea 属于独立模态路由，不是重复的整页框架。

## 验证

- 全部移动端测试 164 项通过，包含视觉基线。
- 新增/扩展布局验证：320×568、390×844、844×390、834×1194、1194×834；系统顶部/底部安全区；1.3 倍字体及长账户文本。
- 验证认证前后与主 Tab 的品牌矩形一致；滚动不改变头部；末尾设置可达且不被导航遮挡。
- 验证四步引导完成、草稿字段与保存按钮避让键盘、二级返回、登录、OCR、拍照批次、聊天生成保存及学习手势。
- 更新并目视检查卡包详情、引导、草稿、聊天等截图。
- 同步一条与现有卡片组件测试矛盾的旧断言：显示“查看提示”按钮，但实际提示在点击前必须隐藏；提示对熟悉度的影响仍受测试保护。
- WebView 外壳通过静态检查；未在本次运行真实设备上的网页加载/相机/系统键盘集成测试。
