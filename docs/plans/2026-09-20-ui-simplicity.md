# UI 原则：简洁，用界面和交互表达产品

来自用户的明确要求：应用要简洁，用 UI、UE 体现产品，不堆积解释文案。

- 学习内容是主体。释义、例句、诗词和注释可以丰富；围绕它们的操作说明应尽量少。
- 滚动使用原生滚动条，选择使用选中态，生成使用进度状态。不要再用常驻句子解释这些行为。
- 卡片本身已经呈现生成结果，不重复播报“已生成”“已应用”，不在每条消息里重复正反面规则。
- 一个状态只表达一次。保存入口已表达待保存状态，不另加“当前草稿 · 尚未保存”；单张卡不显示无用的页数和禁用翻页按钮。
- 每个阶段有明确的主要操作。生成完成后突出保存，重新生成是次要操作。
- 必要信息保留：短操作名称、示例/预览标记、错误、澄清问题、来源说明与内容疑点。精简不能掩盖内容不确定性。
- 图标保留语义标签、tooltip 和可用的点击区域；无障碍说明不必成为所有人常驻可见的文案。

卡片阅读区、制卡对话、排版选择、预览操作、生成与保存操作。其他页面沿用此原则，后续修改时执行。
