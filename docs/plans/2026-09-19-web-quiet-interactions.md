# Loopcard Web: quiet interactions

User direction: a quiet, tactile pocket card collection. Preserve the established paper, ink, serif typography, and teal recall signal. Reduce interface copy; let cards, controls, progress and restrained movement explain the product.

- Home: interactive card first, a small deck collection, and progressively disclosed FAQ content matching the existing structured data. Keep metadata, canonical routes, article content and deck descriptions.
- Study: a single card stage, progress, reveal, then rating. Undo and help remain reachable. Card arrival and face changes communicate state; respect reduced motion. Do not imply that the existing local rating implementation reschedules cards.
- Editor: title and front/back are primary. Subtitle, type and visibility live under settings; defaults and saved values remain intact. A reversible card preview replaces explanatory placeholders. Keep bulk import, reorder, remove and save.
- Library/account: smaller headings, compact empty states, fewer repeated explanations, and the same paper surface as the cards.
- Market: preserve discovery and SEO descriptions; shorten preview framing and remove misleading “tap to reveal” instructions from links that open a deck.

No backend or data model changes. Existing mobile and plugin changes are outside this work.
