# 百度 OCR 相机识别设计

## 目标

在 LoopCard 首页点击“拍照生成卡片”后只打开系统相机，将照片提交给百度通用文字识别高精度接口，提取英文单词，并在确认页以默认全选的列表展示结果。

## 架构

页面层只依赖 `WordCaptureFlow`，不直接接触百度凭据或 HTTP。当前的 `DirectBaiduWordCaptureFlow` 负责调用系统相机、读取照片，再委托 `BaiduOcrService` 完成访问令牌获取和 OCR。未来引入后端时，用调用自有 `/ocr` 接口的新实现替换该 flow，首页和结果页无需修改。

开发阶段从 `.env` 读取 `apiKey`、`secretKey` 和可选的 `BDAppID`。`.env` 不进入 Git，但因为 Flutter asset 会被打入 APK/IPA，该方式仅用于本地测试和 MVP，不作为生产密钥保护措施。

## 数据流

1. 用户点击首页拍摄卡片。
2. 系统相机返回压缩后的 JPEG 图片；取消拍摄则停留在首页。
3. 百度服务通过 API Key 和 Secret Key 获取并缓存 access token。
4. 图片以 Base64 形式提交到 `accurate_basic`，语言设置为英文并请求方向检测和置信度。
5. 将返回文本按英文单词规则切分，支持撇号和连字符，忽略大小写去重并过滤单字符噪声。
6. 有结果时进入确认页；无结果或请求失败时在首页显示明确提示。

## UI 与错误处理

请求期间首页拍摄卡片显示加载状态并阻止重复点击。确认页默认勾选所有单词，允许逐项取消；暂不创建闪卡，保留“已选择 N 个单词”的确认反馈。相机取消不报错；缺少配置、网络失败、百度接口错误和空结果分别显示用户可理解的信息，日志和错误文本不包含凭据或 access token。

## 测试

单元测试覆盖单词提取、稳定去重、令牌请求、OCR 请求、百度错误响应与令牌缓存。Widget 测试覆盖加载状态、成功导航、相机取消、错误提示和确认页选择行为。最终运行 `flutter test` 与 `flutter analyze`。
