# 多图拍照与 Card Agent 对话生成需求

日期：2026-09-19
状态：核心流程已实现；验证结果和运行边界见 [实施记录](2026-09-19-card-agent-implementation.md)。

本文扩展 [Trusted Word Loop MVP](2026-09-13-trusted-word-loop.md) 和
[Word-card generation Skill design](2026-09-13-word-card-generation-skill.md)。
新流程替代拍照入口的“单张拍照后直接生成”路径；学习、复习和保存确认流程沿用现有约定。

## 1. 多张照片作为一批生成素材

- 拍照生成支持连续拍摄多张照片，在提交前展示本批次照片列表、缩略图和数量。
- 支持查看单张照片、重拍指定照片、继续补拍以及删除不需要的照片。
- 重拍成功后仅替换选中照片；取消重拍或拍摄失败时保留原照片及其他照片。
- 补拍追加到当前批次，删除仅移除对应照片及其识别结果。
- 提交前保留现有识别结果校对和选择能力，并能区分内容来自哪张照片；跨照片重复内容应合并，保留来源关系。
- 一次提交包含当前保留的全部照片对应的素材，不能仅提交最后拍摄的一张。
- 空批次不能提交。单张识别失败时明确标注，允许重试、重拍或删除，不丢失其他照片，也不能静默遗漏失败照片。
- 取消系统相机返回本批次编辑界面，保留已拍照片。

## 2. 提交后进入生成对话页面

此处“提交”指提交拍照素材启动生成会话，不是将生成卡片保存到卡组。

主流程：

1. 拍照生成 → 拍摄并管理多张照片。
2. 校对本批次识别内容 → 一次提交。
3. 进入生成对话页，展示本次素材摘要及 Card Agent 的引导消息。
4. Card Agent 在消息中提供几个适合当前素材的常用正反面排版方案；用户可直接选用，也可通过对话定制。
5. 选用方案后，在聊天消息内直接渲染卡片正反面预览；Card Agent 根据所选 Skill、排版方案和本会话规则生成卡片草稿，草稿也在消息内渲染。
6. 用户继续对话调整规则并重新生成，或编辑、删除草稿。
7. 用户确认草稿及目标卡组后保存，进入既有卡组和学习流程。

对话要求：

- 对话消息连接实际 Card Agent 服务；不能只展示模拟回复或将固定生成请求包装成聊天界面。
- 会话保持本批素材、消息历史、当前 Skill、正反面规则和生成结果的关联。
- 支持自然语言定制，例如“正面只显示英文单词，背面用中文解释并附一个例句”，或“正面出问题，背面给答案和推导步骤”。
- 生成前让用户看见当前规则摘要；用户可以直接要求按默认规则生成，也可以先调整规则。
- 修改规则后明确新结果采用的规则，避免把旧草稿误认为最新结果；重新生成不得静默覆盖手工修改。
- 显示发送中、生成中、成功和失败状态。服务异常可重试，保留素材和对话；重复点击或网络重试不能重复保存卡片。
- 返回或重新进入未完成会话时，应能继续；具体持久化方式在实现设计中确定。

### 2.1 常用排版方案提示与直接选用

- 在对话中主动提供几个常用方案，以可点击选项展示；用户无需自己编写提示词即可选用。
- 每个方案说明名称、正面内容、背面内容及排版组织方式。推荐应匹配当前素材和 Skill 支持的能力。
- 选择方案即应用相应正反面规则与排版配置，并在对话中展示已选方案及卡片预览。
- 用户可以切换方案，或继续用自然语言调整，例如“背面先显示例句，再显示释义”。调整结果继续在消息中预览。
- 方案同时定义内容组织与视觉排版，不能只是换一段提示文案；同一种 Skill 可以支持多种方案。

建议的常用方案示例（具体方案以对应 Skill 的支持能力为准）：

| 方案 | 正面排版 | 背面排版 |
| --- | --- | --- |
| 简洁单词 | 单词居中，音标作为次级信息 | 释义在上，例句在下，纵向分区 |
| 单词详解 | 单词为主标题，音标与词性为辅助信息 | 释义、例句与搭配、易混淆点按栏目排列 |
| 知识问答 | 问题突出显示，必要背景作为辅助信息 | 答案优先，解释或推导步骤在下方展开 |

### 2.2 聊天消息内的卡片预览

- 选择方案后，直接在 chat message 中渲染卡片组件，用户无需跳转页面才能查看正反面；文字描述、图片链接或“查看预览”按钮不能替代内嵌卡片。
- 正面和背面均可在消息内查看，并有清晰标识；可采用双面展示或翻面交互，具体方式在界面设计中确定。
- 预览体现所选方案的实际内容顺序、字号层级、分区与布局，并复用正式卡片的渲染规则，保证保存后的展示一致。
- 优先使用本批素材生成示例卡；真实内容尚未生成时，可以先展示明确标注的排版示例，同时显示生成状态，不能将占位内容冒充生成结果。
- 生成后的真实草稿继续以内嵌卡片展示；多张草稿应可浏览，并显示数量和当前位置。
- 切换方案或修改规则后展示对应的新预览，历史消息保留其原有方案与结果，明确当前采用的版本。
- 消息中的预览关联方案标识、规则版本和对应草稿；重新进入会话后仍能恢复卡片渲染，而非退化为纯文本。
- 选用方案和预览均不代表确认保存，仍由用户确认后写入卡组。

## 3. 通过 Skill 支持多种生成逻辑

- Card Agent 通过可扩展的 Skill 机制选择和执行生成逻辑，不能将所有类型硬编码为同一套单词卡提示词。
- 每个生成 Skill 定义适用素材、输入要求、默认正面规则、默认背面规则、可定制参数、输出结构和内容质量校验规则。
- Skill 声明可用的正反面排版方案及其配置，供 Agent 推荐、用户直接选用和客户端渲染；生成结果同时记录所选方案及用户调整。
- 对话负责将用户要求转为当前 Skill 支持的配置；用户可以独立定制正面和背面的内容、语言、详略及栏目。
- Skill 不支持某项要求时，Agent 解释限制，并提供调整规则或切换 Skill 的路径，不能假装执行成功。
- 生成结果关联 Skill 标识、版本及本次规则快照，便于后续修改、重试和追踪。
- 生成结果经结构与内容校验后作为草稿返回，沿用“用户确认后才保存”的边界。
- 新增 Skill 应通过注册和实现其契约接入；拍照与对话主流程无需为每种卡片重写。

建议首批用两类 Skill 验证扩展能力，具体清单在实现时确定：

| Skill | 正面默认内容 | 背面默认内容 | 可定制示例 |
| --- | --- | --- | --- |
| 单词卡 | 英文单词 | 释义、例句与搭配、易混淆点 | 解释语言、例句数量、栏目选择 |
| 知识问答卡 | 根据素材提炼的问题 | 答案与解释 | 提问方式、答案详略、是否包含步骤 |

现有 `word-card-generation` Skill 是单词卡逻辑的基础。现有固定背面结构调整为该 Skill 的默认配置，不能成为所有卡片类型的强制结构；音标、词性和事实准确性等质量约束仍需保留。

## 4. 实现边界与待定项

- 当前拍照入口使用设备端 OCR；本需求中的“一起提交”首先表示整批素材进入同一生成会话，并不自动要求上传原始照片。是否由 Card Agent 直接理解图片、照片存储位置与生命周期，需要在实现设计中明确。
- 每批照片数量、文件大小和每次生成卡片数量的上限需要确定并在界面说明；现有单词生成上限不能直接当作照片数量上限。
- Card Agent 的部署方式、对话协议、会话存储及 Skill 运行机制尚未确定；现有一次性生成接口需要扩展或由 Agent 服务调用。
- 当前客户端和服务端以单词卡草稿为主，接入其他 Skill 时需要明确通用卡片契约及对应预览、编辑和保存能力。
- 本需求以移动端拍照入口为范围；其他入口是否复用对话页可在后续设计中确定。

## 5. 验收标准

1. 连拍三张照片，重拍第二张、删除第一张、再补拍一张，最终提交的素材准确对应当前保留的三张照片。
2. 取消补拍或重拍、单张识别失败时，其他已拍照片及识别结果不丢失；删除所有照片后提交按钮不可用。
3. 批量提交后进入生成对话页，整批素材可追溯，不直接跳至草稿保存页。
4. 用户通过真实 Card Agent 对话分别修改正面和背面规则，生成结果符合修改后的要求。
5. 至少两种 Skill 能通过同一会话流程生成不同结构的卡片，且能预览、编辑及保存。
6. 对话修改规则后能重新生成；草稿与对应规则版本一致，用户编辑不会被静默覆盖。
7. 服务失败可重试，退出后能继续未完成会话；重复提交不会创建重复卡片。
8. 未经用户确认，任何生成结果都不会写入正式卡组。
9. 进入生成对话后可看到多个适用的常用正反面排版方案；点击任一方案即可应用，无需输入提示词。
10. 选用方案后，聊天消息内直接显示对应卡片，并能查看正反面；预览的内容组织与排版符合该方案，无需跳转页面。
11. 切换方案或通过对话调整栏目顺序后，消息内出现对应的新预览；历史预览与当前方案不会混淆。
12. 排版示例和真实草稿有明确区分；真实草稿预览与保存后的卡片展示一致，恢复会话后内嵌预览仍然可用。
