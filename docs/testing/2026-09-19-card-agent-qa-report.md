# Card Agent 单词、诗词、古文问答测试报告

执行日期：2026-09-19（北京时间）。测试对象为当前工作区的 Card Agent，地址 `http://127.0.0.1:54321/functions/v1/card-agent`。

## 结论

真实问答尚未通过验收。10 组场景均实际发送了首轮请求，均返回 `502 {"error":"provider_error"}`，没有得到自然语言回复或生成卡片。进一步直接调用上游模型服务的认证接口返回 `401 invalid_api_key`。后续对话与整批生成因首轮失败而未执行，不将其记为已测，也不使用模拟回答代替实际结果。

本次仅在临时启动的本地服务中尝试了项目文档所指向的本地 Supabase 环境中的 OpenAI 凭据，模型按现有默认配置为 `gpt-4o-mini`。没有修改生产配置或部署线上。临时测试账号已删除，报告不包含密钥或登录令牌。

## 当前产品能力与待补验收

- 目前只有 `word` 和 `knowledge` 两种 Skill，预设为简洁单词、单词详解、知识问答。诗词和古文可以尝试通过知识问答规则表达，尚无专用模板；本轮无法验证模型是否会正确切换或遵守这些规则。
- 本轮问答直接提交文字素材，未通过相机。当前移动端 OCR 使用 `TextRecognitionScript.latin`，没有配置中文识别模型，因此中文诗词/古文的拍照识别入口还需单独支持和真机验收。
- 需要有效模型凭据后重新运行同一组用例，补齐实际回复、追问后的规则变化、卡片原文/释义准确性、栏目顺序及来源关联检查。HTTP 200 也不自动代表语义通过，仍需逐项审核内容。

## 复现

先在本地启动配置了有效模型凭据的 Card Agent，再运行：

```sh
python3 supabase/tests/card-agent/run_scenarios.py
```

该脚本只允许本地服务地址，临时创建并清理测试账号，保存真实服务响应，不模拟模型回复。当前结果的模型记录对应本次服务默认配置；切换服务模型后应同步记录实际配置。

单独验证展示与契约：

```sh
deno test supabase/functions/_shared/card_agent_test.ts
cd apps/mobile
flutter test --no-pub test/card_agent_content_types_test.dart
```
